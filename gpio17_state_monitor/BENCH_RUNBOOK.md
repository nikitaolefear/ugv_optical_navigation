# Стенд гальм і Web ARM

Порядок встановлення та відкату в [INSTALL_PLAN.md](INSTALL_PLAN.md). Поточний етап — інертні артефакти. Активні unit, файли production, Pixhawk та обладнання залишені як є.

## 1. Ізоляція та backup

Після погодження зафіксувати ровер і фізично відокремити живлення обох VESC. Перевірити відсутність напруги на їхніх силових входах. Підготувати штатне живлення Pi/Pixhawk і окремий перевірений шлях живлення сервоприводів, який не подає енергію назад на тягову гілку. Для першого виміру підключити аналізатор до виходів 5/6 замість сервоприводів.

Зберегти підготовлені unit dump і SQLite backup DISARM ledger. Перед cutover дозняти `auth.sqlite3` штатним SQLite backup API з привілейованого сеансу в окремий приватний каталог і перевірити `PRAGMA integrity_check`. Зберегти ідентифікатор firmware, копію `APM/scripts` та контрольні суми зі знеструмленого Pixhawk SD, якщо ця карта знімна. Зберегти актуальний експорт параметрів за процедурою нижче. Знімки неповної конфігурації не використовувати для rollback.

## 2. Read-only експорт без повного cutover

Застосувати `pixhawk-export-readonly.patch` лише на копію чинного релізу owner. Зберегти production inhibit і підтвердити Web ARM OFF. У погодженому вікні переключити лише єдиного owner на цю копію з усіма чинними аргументами ExternalNav і додатковим `--export-pixhawk-params`. Прапор несумісний з іншими діагностичними режимами й не використовує другий serial-сеанс. Після старту owner за свіжого DISARMED і відсутності транзакції робить один адресний `PARAM_REQUEST_LIST` до Pixhawk 1/1. Неповний результат не стає файлом backup. Видимі актуальні параметри є знімком MAVLink-експорту. Встановлення або зміна параметрів під час знімка заборонені.

З кореня repo після появи стану COMPLETE:

```sh
python3 -B ugv_bench_artifacts/fetch_pixhawk_export.py ugv_bench_artifacts/backup/pixhawk-before.parm
```

Якщо GET повідомляє WAITING, READING, INCOMPLETE або INVALID, не використовувати такий знімок для rollback. Якщо треба повторити повний запит, погодити новий діагностичний запуск. Після збереження експорту повернути stock owner без прапора або перейти до погодженого cutover за основним планом.

## 3. Параметри та приймання

- Після перевірки ексклюзивності функцій використати `SERVO5_FUNCTION=94` та `SERVO6_FUNCTION=95` у погодженому стендовому профілі. `SCR_ENABLE=1` потрібний тільки якщо scripting вимкнений. Додати біт 1 до чинного `RC_OPTIONS`, якщо відсутній, після перевірки залежностей RC override.
- Для першого стенда використати діапазони 999–2000 мкс і точки Lua з плану гальм після окремого погодження. Підтвердити `UGVB_LINK` та `UGVB_STEP`. Зберегти `SERVO5/6_TRIM/REVERSED`, safety, failsafe і решту виходів. Перевірити запас механічного ходу перед підключенням сервоприводів.
- Для скороченого циклу звіряти свіжий SERVO_OUTPUT_RAW на 5/6 та фактичне положення обох гальм за спостереженням оператора. До підтвердження реального InterlockIO перевірка на обладнанні обмежена стартовим APPLY та його утриманням.
- Для Web ARM спочатку підтвердити справний апаратний interlock, утримання відсікання, свіжий DISARMED у HOLD, PreArm, відсутність failsafe та живий окремий DISARM. Потім перевірити readiness через GET із дозволеною сесією після окремої активації поточного boot. Будь-яка реальна ARM/DISARM або команда, що рухає серво, потребує окремого дозволу оператора навіть на ізольованому стенді. Повернути opt-in після тесту у стан OFF.

Архіви не активують unit і не змінюють production. Rollback використовує вихідні дерева, збережені unit/drop-in і фактичний snapshot параметрів. STOP/ARM журнали і чинний DISARM ledger зберігаються.

Актуальний baseline із 921 параметра та відмінність реверсу виходів описані в [плані гальм](BRAKE_INTEGRATION.md#базова-конфігурація-стенда-з-актуального-експорту).
