# Один стендовий цикл з кнопки Web RESET

Підготовлено офлайн. Розміщення, підписи й CSS кнопок не змінюються. У явно дозволеній стендовій копії натискання на наявну кнопку RESET спочатку показує окреме підтвердження фізичної ізоляції, а потім виконує **BENCH_RELEASE**. Запит іде за маршрутом `POST /api/bench-brakes/release` → gateway → RPC `BENCH_RELEASE` → єдиний owner → стендовий Lua. Для запиту діють чинні сесія, `stop.reset`, origin, CSRF та окремий ID оператора в owner. Аудит має дію `bench.brake.release`. Відповідь `bench_release_accepted` означає лише постановку в чергу. `STOP_RESET` недоступний у стендовому профілі. `STOP_LATCH=true`, `reset_available=false` і `physical_drive_interlocked=false` залишаються фактичними. Апаратні сигнали InterlockIO не створюються й не імітуються.

## Після окремого погодження

1. Підтвердити знеструмлення обох VESC, опори, нерухомі колеса, вільні тяги та можливість негайного фізичного припинення тесту. CH8 поставити в APPLY. Зберегти чинний активний Lua, ефективні unit/drop-ins owner, gateway, HMI та контрольні суми. Зберегти чинні DISARM inhibit, STOP_LATCH і `UGVB_APPLY_ONLY=1`. LINK=2, STEP=300, точки 999/2000 та конфігурацію 94/95 не змінювати.
2. На **окрему** копію owner накласти `owner.patch`, скопіювати `bench_brake_link.py` та `web_bench_brake_link.py` у `production_stop/`, накласти `web-owner.patch`. Використати ту саму основу й шлях привілейованого opener, що в чинному HOLD-only профілі. Профіль зберігає `--functional-brake-boot-id <поточний Pi boot UUID> --brake-hold-only --externalnav-observe-only --observe-brake-pwm` і додає `--isolated-brake-cycle VESC_ISOLATED_OPERATOR_PRESENT --bench-web-release-boot-id <той самий UUID> --bench-web-operator-id <ID одного вже уповноваженого оператора>`. Чинні сокети, peer UIDs/GIDs і ledger зберегти. Ця копія відхиляє isolated-профіль без Web opt-in.
3. На **окрему** копію frontend/gateway з чинним candidate overlay накласти `web-frontend.patch`. Gateway запускати з `--bench-release-boot-id <той самий UUID>` без `--enable-disarm`, `--enable-stop-reset` і `--web-arm-boot-id`. Для HMI застосувати тільки тимчасове `UGV_HMI_BENCH_RELEASE_BOOT_ID=<той самий UUID>`, залишити ARM і Web DISARM вимкненими. Попередні unit/drop-ins лишаються для відкату.
4. В ексклюзивному погодженому maintenance-сеансі зупинити owner, підтвердити вільний USB, зберегти старий Lua під неактивним іменем і встановити `ugv_brake_bench.lua` як єдиний активний `ugv_brake.lua`. Звірити файл після зворотного читання. Після погодженого перезапуску Pixhawk закрити maintenance-сеанс і повернути одного owner зі стендовою копією, потім тимчасові gateway і HMI. Використати чинну процедуру перевірки залишкових Unix-сокетів. Під час перезапуску безперервність PWM не підтверджена; шасі має утримуватися опорами незалежно від гальм. Підготувати журнали до запуску: стан FRONT/latch, bench RPC/audit, `UGVB_BENCH_*` і свіжий SERVO_OUTPUT_RAW.

## Один тест

1. Із CH8 у APPLY та відпущеним бампером підтвердити один serial-owner, DISARMED, inhibit, STOP_LATCH=true, ExternalNav TX=false/sent=0, свіжі 999/999 і Lua `UGVB_BENCH_READY`. Owner тримає вікно підготовки до 30 секунд від запуску. Дозволений оператор один раз переводить CH8 у RELEASE. PWM має залишитися 999/999, доки не надійде запит від кнопки.
2. Коли стендовий статус показує готовність, натиснути RESET один раз і підтвердити стендовий RELEASE у браузері. Очікувати `BENCH_WEB_RELEASE_QUEUED`, `BENCH_WEB_RELEASE_SENT`, `UGVB_BENCH_RELEASE` і свіжі 2000/2000. Оператор фізично підтверджує відпускання обох коліс без доступу рук до рухомих тяг. Клік не скидає STOP_LATCH. Owner має 0,5 с на dispatch, RELEASE діє максимум 3 с, Lua не подовжує абсолютний таймер новими KEEP.
3. У межах RELEASE оператор один раз натискає GPIO17 та відпускає. **PASS:** після підтверджених 2000/2000 і фізичного відпускання записано `FRONT_PRESSED`, причина завершення owner `BENCH_GPIO_STOP`, час HOLD у `UGVB_BENCH_APPLY_REQ HOLD <sent_ms>` пізніший за натискання, обидва виходи повернулися до свіжих 999/999, обидва колеса затиснуті. Після відпускання STOP_LATCH=true та фізичне утримання зберігаються. Завершити в CH8 APPLY. APPLY від таймауту до натискання, втрата доказів, несподіваний рух або лише частковий хід — FAIL без повтору.
4. STOP, втрата GPIO/RC або помилка припиняють дозвіл, owner надсилає HOLD коли serial доступний. При втраті owner↔Pixhawk Lua повертається до APPLY за lease 350 мс без KEEP. Якщо HTTP-відповідь втрачена, припинити тест без повтору: уже прийнятий запит може виконуватися до кінця короткого вікна. Програмний HOLD і телеметрія не гарантують механічного затискання при втраті живлення.

## Відкат

Після PASS або FAIL повернути CH8 у APPLY. Якщо є несподіваний рух, оператор негайно припиняє тест фізично. Зберегти ізоляцію VESC. Зупинити тимчасові профілі HMI/gateway/owner, підтвердити вільний serial, відновити попередній активний Lua та перевірити його SHA-256. Прибрати лише стендові drop-ins і Web opt-in, закрити maintenance-сеанс і повернути попередні HMI/gateway та одного HOLD-only owner після погодженого запуску Pixhawk. `UGVB_APPLY_ONLY=1` зберігався протягом тесту; звірити його й свіжі DISARMED, 999/999, inhibit, STOP_LATCH і ExternalNav sent=0.

До погодженого встановлення цей пакет лишається офлайн.
