# Один цикл RELEASE → GPIO17 STOP → APPLY на ізольованому стенді

Окремий тимчасовий профіль. Штатні джерела candidate, активний Lua та owner при підготовці не змінюються. Цей профіль не підключає InterlockIO і не підтверджує фізичного відсікання. Його використання залежить від перевіреної фізичної ізоляції тяги та присутності оператора. Web RESET, Web ARM і дозвіл тяги лишаються OFF. DISARM inhibit та STOP_LATCH=true зберігаються навіть під час стендового RELEASE.

## Встановлення тільки після окремого погодження

1. Підтвердити фізичне знеструмлення **обох VESC**, закріплене шасі, колеса над землею, вільну зону гальмівних тяг, можливість негайно припинити тест фізичним вимикачем. Встановити CH8 в APPLY (999 мкс), залишити GPIO17 відпущеним. Зберегти чинний unit/drop-in, активний Lua та його SHA-256. Під час підготовки не записувати параметри. Чинні LINK=2, STEP=300, APPLY_ONLY=1, L/R 999/2000, FUNCTION 94/95 і межі 999–2000 використовуються як передумови.
2. Підготувати окрему копію **чинного HOLD-only дерева owner**. Накласти на корінь копії `owner.patch` через `patch --fuzz=0 -p1` і скопіювати `bench_brake_link.py` у `production_stop/`. Тимчасовий root-owned drop-in вказує на цю копію, зберігає чинні сокети, ledger, `--functional-brake-boot-id <чинний UUID>`, `--brake-hold-only --externalnav-observe-only --observe-brake-pwm` і додає `--isolated-brake-cycle VESC_ISOLATED_OPERATOR_PRESENT`. У погодженому виключному maintenance-сеансі замінити лише активний `/APM/scripts/ugv_brake.lua` на `ugv_brake_bench.lua`; зберегти попередній файл з неактивним суфіксом і звірити новий через зворотне читання. Після одного погодженого перезапуску Pixhawk закрити MAVFTP і повернути один owner. Переривання PWM при перезапуску можливе. Шасі в цей час утримують опори.
3. Запустити пасивний запис журналу, `/api/production-stop` і `/api/owner-diagnostics` до початку циклу. Допуск: свіжий DISARMED, STOP_LATCH=true, ExternalNav TX=false/sent=0, GPIO17 відпущений, CH8 у APPLY, три свіжі PWM 999/999, `brake_release=BENCH_READY` та свіжий `UGVB_BENCH_READY` від Lua. Owner чекає готовності й дії оператора не довше 30 с від свого запуску. Якщо стартові умови або час не дозволяють безпечно провести цикл, залишити CH8 у APPLY та завершити без спроби.

## Один фізичний цикл

1. Після явного сигналу готовності оператор **один раз** переводить CH8 з APPLY в RELEASE. Owner передає один стендовий RELEASE через чинний serial FD. Очікувати `UGVB_BENCH_RELEASE`, свіжі SERVO5/6=2000/2000 та видиме відпускання обох механізмів. Сценарій має до трьох секунд від прийнятого RELEASE; KEEP не подовжує цей час. Під час руху механізмів не заходити в зону тяг.
2. У межах цього вікна оператор **один раз** натискає GPIO17. Очікувати `FRONT_PRESSED`, причину завершення `BENCH_GPIO_STOP` у стані owner, відповідний `UGVB_BENCH_APPLY_REQ HOLD <sent_ms>` з часом пакета після натиску, свіжі 999/999 та окреме фізичне підтвердження утримання обох коліс. Після відпускання GPIO17 обидва гальма залишаються в APPLY. Повернути CH8 в APPLY.
3. **PASS:** обидва виходи та обидва гальма фактично відпущені перед натисканням, GPIO17 зафіксований, Lua підтвердив HOLD після натиску, обидва виходи повернулися на 999, обидва колеса фізично утримуються. STOP_LATCH лишився true. Якщо APPLY почався через таймаут або CH8 раніше за GPIO17, тест причинного переходу від GPIO17 не пройдено. Будь-яка невідповідність, відсутнє підтвердження, обрив запису чи несподіваний рух — FAIL, припинити тест, повторно RELEASE не просити.

## Автоматичне завершення та відкат

- Перший RELEASE витрачає дозвіл. Натискання STOP або невідомий GPIO після готовності незворотно закінчує спробу в owner, навіть якщо бампер відпустили між serial ticks. Lua відкидає RELEASE, якщо в тій самій вибірці є HOLD. Після втрати свіжих повідомлень Lua повертається до APPLY за lease 350 мс. Повернення RC8 в APPLY, втрата RC8 та закінчення абсолютного вікна також відкликають RELEASE. Не перезапускати стендовий профіль автоматично.
- Після PASS або FAIL повернути CH8 у APPLY і припинити стендову передачу. Якщо є несподіваний фізичний рух або утримання не підтверджується, оператор застосовує підготовлене фізичне припинення тесту. Зберегти ізоляцію VESC, закріплене шасі та відсутність руху. Коли стан стабільний, зупинити лише стендового owner, перевірити відсутність власника порту, через MAVFTP відновити збережений Lua та звірити SHA-256. Прибрати лише стендовий drop-in, перевірити залишковий backend.sock за попередньою процедурою та повернути попередній HOLD-only профіль після погодженого перезапуску Pixhawk. Підтвердити 999/999, DISARMED, STOP_LATCH=true і ExternalNav sent=0. Параметри для такого відкату змінювати не потрібно.
- Lua і owner керують командним PWM. Без живлення Pixhawk або під час перезапуску програмного підтвердження фізичного APPLY немає. Розрахунковий ramp 4 цикли по 50 мс не включає фактичний час руху механізму. Мітки MAVLink підтверджують доставку повідомлень; фізичне утримання підтверджує оператор.
