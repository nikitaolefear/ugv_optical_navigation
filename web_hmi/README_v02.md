# UGV №1 — HMI v0.2

Виключно програмний симулятор. Жодного підключення до Pixhawk, MAVLink,
USB, CAN або VESC. Фізичний CAN залишити відключеним.
Попередня версія збережена в app_v01_backup.py.

## Поведінка

- №1: A (0 м) → B (10 м), +0.5 м/с.
- №2: B (10 м) → A (0 м), −0.5 м/с; корпус завжди 0°.
- READY: вибір місії; START тільки після підтвердження.
- MOVING: PAUSE → PAUSED. Номер місії, напрямок, прогрес і ціль зберігаються.
- PAUSED: лише окремий RESUME продовжує попередню місію з тієї ж позиції.
  Час у паузі не додається до руху; START у PAUSED заборонений.
- HOLD: безпечна зупинка через API hold, RESUME та START заборонені.
- STOP: скасування місії, стан STOPPED; RESUME та START заборонені.
- FAULT та E_STOP: аварійне блокування, RESUME та START заборонені.
  STOP/HOLD не знімають аварійне блокування.
- COMPLETE: повторний START заборонений, потрібен RESET.
- FAULT: імітація помилки або збій годинника; потрібен RESET.
- RESET з будь-якого стану повертає на початок обраної місії у READY.
- RESET скидає лише програмні блокування DEMO. Для нового руху потрібен
  окремий START із підтвердженням; RESUME після RESET заборонений.

Стан зберігається в пам'яті одного серверного процесу. Браузер лише опитує
сервер раз на 500 мс. Рух обчислюється за серверним монотонним часом:
наступний запит враховує весь час без відкритого браузера.
Перезапуск процесу створює новий READY, без автоматичного руху.
Не запускати кілька workers: стан між процесами не спільний.
Журнал містить останні 100 подій поточного процесу.

API: GET /api/status; POST /api/command із JSON:
{"action":"start","confirmed":true,"revision":0,"request_id":"unique-id"}.
Дії: select (mission: 1 або 2), start, pause, resume, stop, hold, reset, fault, estop.
Кожна команда потребує request_id; останні 256 ідентифікаторів захищені від
повторного виконання. revision захищає від застарілого стану; stop/hold/fault/estop
приймаються незалежно від revision. Повторний RESUME з тим самим request_id
не виконується знову; інший RESUME поза PAUSED відхиляється. Некоректні команди: HTTP 409,
некоректний формат JSON: HTTP 400. Підтвердження START прив'язане до
ревізії, показаної під час відкриття діалогу.

## Межа майбутнього реального RESUME

Метод Simulator._resume_precheck — окрема точка перевірки виключно DEMO.
Він дозволяє продовження лише з PAUSED і не надає дозволу фізичному роверу.
У API resume_precheck явно повертає real_resume_supported=false та список
майбутніх обов'язкових перевірок. Жодна з них зараз не вважається пройденою.

Майбутній реальний контролер має виконувати окремий PRECHECK перед кожним
RESUME: свіжа позиція ArUco, справний EKF, відсутність перешкод, відсутність
активних захистів, нульова швидкість і перевірений маршрут. За відсутності
або застарілості доказів будь-якої перевірки рух має залишатися заблокованим.
Скидання фізичних аварійних захистів потребуватиме окремої політики;
поточний RESET поширюється тільки на програмний симулятор.

## Тести без запуску сервера

З кореня проєкту:

```bash
python3 -m unittest web_hmi.test_hmi -v
```

Тести використовують Flask test_client та штучний годинник: мережевий
порт не відкривається. Перевіряються обидві місії, STOP, продовження,
RESET, FAULT, повтори, конкурентні запити, застарілі ревізії, помилки API
та завантаження сторінки іншим клієнтом без зміни місії.
18 тестів включають START → PAUSE → RESUME → COMPLETE для обох напрямків,
збереження PAUSED після оновлення сторінки, заборону продовження після
STOP/HOLD/FAULT/E-STOP, RESET без руху, повторний та конкурентний RESUME.
Це не браузерний тест відображення; вигляд і дотики на Sigma A1035
потрібно перевірити на самому планшеті.

## Безпечний окремий запуск

Порт за замовчуванням — 8081, прив'язка лише до localhost:

```bash
python3 web_hmi/app.py
```

Адреса: http://127.0.0.1:8081 . Для планшета у довіреній локальній мережі:

```bash
python3 web_hmi/app.py --host 0.0.0.0 --port 8081
```

Відкрити http://IP_RASPBERRY_PI:8081 . Доступ без автентифікації;
використовувати лише у довіреній мережі.

Чинний сервер 8080 не зупинявся й не перезапускався. Заміна app.py на
диску не перемикає процес v0.1 без перезавантаження (debug=False).
Перемикання 8080 потребує окремого підтвердження користувача: спочатку
визначити та контрольовано зупинити чинний процес, перевірити звільнення
порту, потім запустити один процес:

```bash
python3 web_hmi/app.py --host 0.0.0.0 --port 8080
```

Останню команду не виконувати, доки перемикання не погоджено і порт зайнятий.
