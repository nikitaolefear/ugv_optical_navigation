## Зміна

Спільна перевірка для створення і зміни пароля тепер приймає від 8 до 128
Unicode code points включно. Усе поза межами відхиляється до запису нового
хешу. Пробіли також є символами; зокрема початкові й кінцеві не видаляються.
Літери (включно з українськими), цифри, пробіли та спецсимволи дозволені.
Не вимагаються лише цифри, суміш класів чи обов'язкові великі/малі літери.
Немає обрізання, strip, case folding або іншої нормалізації пароля.

MIN_PASSWORD_LENGTH=8 і MAX_PASSWORD_LENGTH=128 визначені в auth.py; CLI
використовує ці самі константи в прихованій підказці. Помилка містить лише
межі, без введеного значення. Login UI показує нову політику та не має
maxlength, який міг би обрізати вставлення довгого пароля або Unicode.
Понад 128 сервер відхиляє, не підміняючи введення його префіксом.
Login не має нового minlength/pattern, щоб не змінювати перевірку існуючих
хешів; це не форма створення нового облікового запису.

Scrypt scrypt:32768:8:1, salt, механізм перевірки хешів і сховище лишаються
без змін. Раніше створені паролі перевіряються як раніше, автоматичного
rehash, скидання паролів чи DB migration немає. CSRF, cookie, серверні
сесії, відкликання, role guards і login rate limits не змінені. Статистика
місій/schema v2 та owner helper не змінюються.

## Перевірки без робочих акаунтів або приватної БД

Повний набір запускати з кореня окремого кандидата саме цим інтерпретатором:

```bash
PYTHONDONTWRITEBYTECODE=1 /home/ugvs2/.venv-ugv-hmi-auth/bin/python -m unittest \
  web_hmi.test_hmi web_hmi.test_pixhawk_telemetry web_hmi.test_pixhawk_owner_helper \
  web_hmi.test_auth web_hmi.test_mission_statistics web_hmi.test_periods_v2 \
  web_hmi.test_password_policy -v
```

Наведені всі сім модулів із TestCase. test_support.py — допоміжні fixtures,
не самостійний top-level test module; запускати його через bare discovery
із -s web_hmi без пакетного контексту не треба.

Нові тести перевіряють:

- 7 і 129 — відмова; 8 і 128 — дозволено, у hash/create/change paths.
- Незмінність існуючого хешу при відхиленій зміні пароля.
- Літери, лише цифри, лише спецсимволи, українські літери, змішані значення,
  лише пробіли, пробіли по краях, Unicode поза BMP; без вимог класів.
- Точне збереження пробілів і відсутність обрізання; неправильне значення
  не перетворюється мовчки на правильне.
- Старий scrypt-хеш без перезапису; вхід після встановлення нового граничного
  пароля через тимчасові fixtures, без доступу до state служби.
- Getpass, відмова без TTY/при echo fallback та реальний псевдотермінал:
  ввід не відображається, пробіли зберігаються. Це не serial-порт.
- Жодного введеного значення, хешу, cookie або токена в audit/CLI output.

Усі значення синтетичні. Самі значення та їхні хеші в test log/report не
виводяться. Тимчасові тестові користувачі існують лише в disposable SQLite
fixtures для перевірки AuthStore; робочі/особисті акаунти не створювалися.
Production DB, службу, sudoers, попередні кандидати та Pixhawk не чіпали.

міграції схеми, видалення сесій або нових sudoers-дозволів. Не запускати
admin_cli create/bootstrap/password проти робочого state в межах цього завдання.

та зміну пароля. Не міняти metadata version і не робити restore приватної БД
для відкату лише цієї зміни. Системні конфігурації в цьому кандидаті не змінені.

Неперевірено: живий веб-браузер/планшет, production rollout/rollback,
сервер/HTTPS/служба та фактичний Pixhawk. Перевірки — локальні unit/integration
і псевдотермінал, без запуску мережевого listener або serial reader.
