# UGV №1 — HMI v0.3

DEMO v0.2 збережено без змін у simulator.py, test_hmi.py, README_v02.md.
Повна копія початкової v0.2: backups/hmi_v02.tar.gz (включає app.py,
HTML, JS, CSS, симулятор, тести та README). Git не використовувався.

## Межі READ-ONLY

Модуль pixhawk_telemetry.py відкриває тільки
`/dev/serial/by-id/usb-Holybro_Pixhawk6C_260025000C51333336373039-if02`
через O_RDONLY | O_NOCTTY | O_NONBLOCK. Налаштування локального tty:
raw, 115200, 8N1, без flow control. Це не зміна параметрів Pixhawk.
MAVLink-парсер: ardupilotmega v2 (декодує також кадри v1), MAVLink(None).
Немає транспортного об'єкта, heartbeat від HMI, write/send, запитів
потоків або команд ARM/DISARM/SET_MODE/REQUEST_MESSAGE/SET_MESSAGE_INTERVAL/
PARAM_SET/MISSION/приводів. HMI не здатна забезпечити DISARM: лише показує
фактично отриманий HEARTBEAT, включно з ARMED, якщо такий надійде.
Ровер повинен залишатися DISARMED; CAN фізично відключений.

DEMO-кнопки викликають тільки Simulator.command. Телеметрія доступна
окремо через GET /api/telemetry; endpoint не приймає POST.
GET /api/status зберігає контракт DEMO v0.2: його armed=None та
physical_telemetry=UNAVAILABLE належать симулятору. Фізичні дані беруться
виключно з /api/telemetry.

Імпорт app/create_app, Flask CLI та звичайний запуск не відкривають USB.
Тільки явний --telemetry запускає один фоновий reader. Один процес,
без reloader, без кількох workers. Після помилки немає автоматичного
повторного відкриття: усуньте причину і контрольовано перезапустіть
окремий v0.3 процес. Робочий сервер без погодження не перезапускати.

## Порт і конкуренція

Перед відкриттям перевіряються видимість /proc/*/fd та fuser, після нього —
flock, TIOCEXCL та повторний fuser. Якщо перевірка /proc неможлива, fuser відсутній, завершився з помилкою
або перевищив тайм-аут: PORT_CHECK_FAILED. Підтверджений власник або
конфлікт flock/TIOCEXCL: PORT_BUSY. Відмова доступу до самого tty:
PORT_ACCESS_DENIED. В усіх цих випадках читання заборонене.
Немає читання до завершення перевірок; чужі процеси не завершуються.
Потрібен Linux, psmisc (fuser), права читання tty і видимість дескрипторів
усіх процесів. Обмеження /proc/hidepid або прав дадуть PORT_CHECK_FAILED;
не обходити цей стан, запускаючи паралельного читача.

Діагностика використовує стандартний logger модуля pixhawk_telemetry
(при пакетному імпорті — web_hmi.pixhawk_telemetry): ERROR містить стан,
етап, PID/UID HMI, шлях, первинний errno, PID власників, результат fuser
(returncode/stdout/stderr, якщо доступні), traceback із ланцюжком причин.
INFO містить кожний завершений виклик fuser; для повного журналу
налаштувати обробник Python logging на INFO. Без окремого обробника
ERROR потрапляє у стандартний stderr. Дані MAVLink у журнал не пишуться.
Помилки перевірки не перетворюються на дозвіл відкривати порт.
Після невдалої повторної перевірки вже відкритий дескриптор закривається
до налаштування tty або читання байтів.

Це консервативний захист, а не атомарна координація з довільним привілейованим
процесом, який може ігнорувати TIOCEXCL. Не запускати інший serial-клієнт
одночасно. Якщо Pixhawk уже обслуговує навігація/MAVProxy/інший процес,
залишити його власником; потрібен окремий MAVLink router з виділеним
каналом телеметрії HMI. Router у v0.3 не реалізований.

## Значення та свіжість

Перший HEARTBEAT компонента 1 з autopilot != INVALID визначає джерело;
інші системи/компоненти відкидаються. До нього дані невідомі.
HEARTBEAT дає ARM/DISARM та mode. Для ArduPilot Rover показується відома
назва режиму, а також custom_mode/base_mode. Для невідомого режиму/типу —
UNKNOWN та числові коди, без вгадування назви.

АКБ: BATTERY_STATUS для батареї id=0, сума доступних комірок voltages і voltages_ext;
резервне джерело SYS_STATUS.voltage_battery. Sentinel 65535 і нульова
напруга не видаються за реальні вимірювання. Yaw: ATTITUDE.yaw у градусах
0–360; це орієнтація оцінювача, не незалежно підтверджений географічний курс.
EKF_STATUS_REPORT і ESTIMATOR_STATUS показують отримані flags, навіть 0;
прапорці не перетворюються на необґрунтований висновок «EKF OK».

Для кожного типу показується вік за локальним монотонним часом приймання.
Поріг свіжості — 3 секунди. Ніколи не отримано: UNKNOWN / value=null.
Після тайм-ауту або відключення: STALE / value=null, без старого числа.
HEARTBEAT визначає CONNECTED; відкритий порт без нього — UNKNOWN.
Порт відсутній/недоступний: PORT_ERROR; EOF/USB помилка під час читання:
DISCONNECTED; бракує пакета: DEPENDENCY_MISSING; читач вимкнений: DISABLED.
У браузері окремий poll кожні 500 мс, запит має тайм-аут 2 с;
помилка HTTP або відсутність оновлення понад 3 с прибирає фізичні значення.
Свіжість означає час приймання, а не доказ актуальності внутрішнього датчика.
Якщо Pixhawk сам не передає потрібний тип, він лишається UNKNOWN:
запитів повідомлень HMI не надсилає.

## Встановлення та окремий запуск

Потрібні Python 3, Flask, pymavlink і системний fuser.
У підготовленому середовищі Python встановити залежності:

```bash
python3 -m pip install -r web_hmi/requirements_v03.txt
```

У цьому сеансі pymavlink відсутній; спроба встановлення в /tmp не вдалася
через DNS. Реальні кадри парсером та фізичний USB не перевірялися.

Для окремого запуску вибрати вільний HTTP-порт (наприклад, 8082), не
зупиняючи робочий Flask. Спершу переконатися, що serial не використовує
інший процес. З кореня проєкту:

```bash
python3 web_hmi/app.py --host 127.0.0.1 --port 8082 --telemetry
```

Відкрити http://127.0.0.1:8082 . Для планшета у довіреній локальній мережі
замінити host на 0.0.0.0; доступ без автентифікації.
Без --telemetry працює тільки DEMO, CONNECTION=DISABLED.
Для наявного робочого порту потрібне окреме погодження перемикання;
у цьому сеансі сервери не запускалися і не перезапускалися.

## Тести

```bash
python3 -m unittest web_hmi.test_hmi web_hmi.test_pixhawk_telemetry -v
```

18 початкових тестів плюс тести телеметрії: незалежні тайм-аути,
відключення/EOF/USB, відсутні значення/EKF, джерело HEARTBEAT, sentinel
АКБ, NaN yaw, busy/error/відсутній порт, відсутня залежність,
O_RDONLY/exclusive, конкурентний власник, невидимі процеси,
ізоляція всіх DEMO-кнопок та структурна заборона send/write.
Тести використовують штучні повідомлення, час, дескриптори і mock парсера;
вони не відкривають Pixhawk. Потрібна окрема ручна перевірка реальної
телеметрії та відображення на планшеті після погодженого запуску.

Для незалежної перевірки збереженої v0.2 (без сервера):

```bash
mkdir -p /tmp/ugv-hmi-v02-check
tar -xzf web_hmi/backups/hmi_v02.tar.gz -C /tmp/ugv-hmi-v02-check
cd /tmp/ugv-hmi-v02-check
python3 -m unittest web_hmi.test_hmi -v
```
