# B2-FTP ListDirectory retry — offline

**Confirmed defect.** The original parser splits on NUL, drops the final delimiter, and rejects the resulting empty record when a Rover 4.7.2 entry has two NUL bytes. Rover's formatters include an explicit NUL in the string and the packer advances by the returned length plus one. The response size is the resulting packed length. Files have F + name + TAB + unsigned size; directories have D + name. ArduPilot omits entries it cannot serialize and counts the serializable entries when skipping the requested offset. The live result was `unsupported directory entry` after ListDirectory ACK. Double NUL is a source-backed hypothesis for that particular reply because the raw packet was unavailable. [Rover 4.7.2 source](https://raw.githubusercontent.com/ArduPilot/ardupilot/Rover-4.7.2/libraries/GCS_MAVLink/GCS_FTP.cpp#L145-L261)

Installed pymavlink 2.4.50 splits ListDirectory data on NUL, discards empty elements, counts nonempty records for pagination, and treats an exact EOF NAK as completion. The retry retains stricter validation. It accepts one or two terminal NULs per record and advances by one for each actual record (including bare S skip markers used by compatible implementations and D./D..). Unknown types, malformed framing, wrong offsets, duplicate names, traversal, invalid unsigned 32-bit sizes and unexpected NAKs are rejected. [MAVLink ListDirectory](https://mavlink.io/en/services/ftp.html#list-directory)

**Private evidence.** On a rejected correlated ListDirectory reply, retain at most one FTP payload (up to 251 bytes before hex encoding) and its header fields. Return it only via the existing checked result IPC to the initiating peer. The client writes at most 1024 bytes to list-directory-failure.json in the private backup, mode 0600, and reports only the reason on stderr. The capture shows the decoded FTP payload including its header and MAVLink-restored padding. A missing reply or a frame discarded before reaching the parser has no capture. No actual SD names or payloads are included here.

**Results.** 33/33 Python tests passed (25 existing plus 8 regressions), including real startup parser with the installed B2 argument template, UID validation with temporary Unix sockets, single/mixed/double NUL, EOF and invalid NAKs, duplicates, rejection of unknown records, capture ownership and private write. Source-shaped multi-page fixture returned all records in order at offsets 0, 3, 5, 7 and 8. Bash syntax checks and three mock rollback scenarios passed. B2 remains unchanged. No live FTP, deployment or service restart was performed.

The isolated deployment package has the combined integration.patch and SHA256SUMS. The incremental list-directory-fix.patch uses paths from the previous deployment package root. Apply it only to an isolated copy of that earlier package to reproduce the runtime changes.
