# Короткий окремий стенд USB/UART

Статус: план, запуск не дозволено. Це перевірка межі запису, не Stage 3 і не оцінка EKF. Не перемикати SRC, не змінювати параметри для цього транспортного тесту.

## Обладнання та допуск

- Pi 5 і Pixhawk 6C з тією самою версією Rover та тим самим кабелем/швидкістю, що плануються для повтору. Стабільне живлення контролера, незалежно від фізично роз'єднаного живлення тяги.
- Для USB CDC: пасивний USB protocol analyzer між Pi і Pixhawk. Якщо перевіряється UART: пасивний logic analyzer на лініях TX/RX з відповідним рівнем напруги й загальною землею. Не підключати другий активний serial client.
- Спільний timing marker із відомим бюджетом похибки, журнал monotonic із timestamps syscall enter/exit, revoke, queue check, watchdog і heartbeat, декодер MAVLink для фізичного capture. usbmon може бути додатковим хост-доказом, але не заміною апаратному capture.
- Окреме погодження оператора, фізична ізоляція тягових двигунів, нерухоме шасі, HOLD/DISARMED, підтверджені inhibit і STOP latch, один owner. Перед початком записати TX=0 і штатний heartbeat. При будь-якій втраті допуску припинити lease і зберегти ізоляцію.

## Короткі фази, лише після дозволу

1. 10 с baseline TX=0. Виміряти інтервал heartbeat і часову розбіжність між host trace та пасивним capture.
2. До 5 с дозволеного безпечного діагностичного потоку через той самий owner. Тип пакета та спосіб його безпечного допуску затвердити окремо. Будь-який ExternalNav packet має проходити чинний guard і окреме погодження; тест не змінює SRC.
3. Відкликати lease вручну. Тримати capture ще 5 с. Повторити коротку фазу окремими сесіями для аварії клієнта та припинення renew; завершувати лише тестовий клієнт. Перевірку EAGAIN/partial write робити спочатку на стендовому приймачі або контрольованій USB-навантажувальній конфігурації з окремим дозволом; не від'єднувати штатний контролер у відкритій сесії.
4. Для кожного прогону зафіксувати t0 (stop або останній renew), gate closed, syscall exit, barrier ack, TIOCOUTQ=0, останній фізичний байт кадру, до/після heartbeat. Записувати bound синхронізації обох вимірювальних каналів.

## PASS/FAIL

- Запропонований стендовий поріг закриття gate після останнього renew: ≤0,85 с включно з похибкою. Для явного STOP окремо виміряти IPC і узгодити бюджет до запуску. Синтетичні результати минулого пакета не є межею для USB.
- Бар'єр TX видається лише після завершення зарезервованого запису. Після підтвердженого бар'єра нових syscall ExternalNav немає. Якщо syscall завис або черга не підтверджена протягом узгодженого bounded timeout, FAIL, без оптимістичного TX=0 або rollback-підтвердження.
- Фізичний capture має показати, скільки ще даних реально пішло після gate і після TIOCOUTQ=0. Фізичне завершення TX зарахувати лише за відсутності пізніх кадрів після задокументованої точки stop та узгодженого transport bound. Непридатна синхронізація або неповний capture означають INCONCLUSIVE.
- Штатний heartbeat продовжується в межах його передтестового профілю й чинного watchdog. Втрата HOLD/DISARMED або heartbeat, будь-який рух, новий TX після бар'єра чи пропущений фізичний доказ — припинити, залишити тягу ізольованою.
- Після кожної спроби зберегти raw capture, узгоджені clocks, версії, хеші, звіт TX/queue/heartbeat. Відновити штатний owner і незалежно підтвердити HOLD/DISARMED/TX=0.
