# Active B3-SW candidate

Offline only. Independent audit and separate operator authorization are required before deployment and each active case. Hardware evidence remains deferred. No test may change SRC, parameters, brake outputs or arm state. Maintain physical isolation.

The candidate derives from the verified B2-LOG overlay and preserves its HMI, optical, Observer, DataFlash and journaling entry points. It adds a fixed ODOMETRY path through the existing sole Owner, using existing pose validation and encoder identity, with a synthetic frame rejected early by the pinned Rover handler. Default is closed. Neither deployment nor the existence of an approval marker opens TX. A checked IPC client must open its one-use scenario nonce and keep renewing. Another operation cannot supply a frame or choose an ID. Startup starts with no authorization. Combined HTTP reports lease state and cumulative successfully written frame count.

## Deployment and rollback

For the current B2-LOG, first verify no pending transaction, no markers, empty queue and DataFlash IDLE. After audit and deployment approval, use the original B2-LOG helper rollback to the pinned B2. Verify one Owner, HOLD, DISARMED, inhibit, STOP latch, fresh 999/999 PWM and TX=0. From pinned B2 run `sudo bash "$PACKAGE/deploy.sh" activate --approved`. The helper pins the base, checks the package, renders the combined full parser and keeps the previous B2 drop-in. On startup/readiness failure it returns to B2. The helper checks the configured socket is inactive before removing it. Deploying starts a new Owner generation, invalidating all prior Indexed Discovery proof. LOG_DISARMED transaction remains unavailable until new authorized discovery. B3 does not need to change LOG_DISARMED.

Rollback after collecting evidence is `sudo bash "$PACKAGE/deploy.sh" rollback --approved`. First revoke the B3 marker and let the gate close. Verify lease inactive, queue empty, journal closed and DataFlash IDLE. The helper revokes both markers, refuses an active B3 case and preserves durable LOG_DISARMED journal. It returns to pinned B2. If required, a separately approved activation of the stock B2-LOG is a distinct step and requires renewed discovery for parameter transactions.

## Future active protocol

After separate approval and 10 s passive baseline, obtain B2-LOG status identity and choose one new 32-hex nonce. A root-owned file named b3-authorization in the log-profile runtime directory contains one newline-terminated line `B3 <hardware> <pi_boot> <fc_boot> <owner_session> <pid> <process_generation> <scenario> <nonce>`. Install it atomically with group/other write disabled under the existing root-owned runtime directory. The approved IPC client uses the established gateway UID/GID and the installed interpreter, socket policy and module path. Run b3_client.py with the same --socket, --owner-uid and --socket-gid flags as log_client.py. Use:
- Manual A: `b3_client.py run --scenario revoke --nonce "$NONCE"`, with the IPC flags and --await-approval. The client logs its request bracket and process identity.
- Termination B: `b3_client.py run --scenario client_exit --nonce "$NONCE"`, with the same flags. A supervisor must timestamp and terminate only that test client while it is renewing. Use b3_supervisor.py as the same unprivileged UID with the client active JSON. It checks PID generation and argv, then uses pidfd signal and exit observation. The kernel process check may lag until reaping. A timed-out supervisor is a failed scenario.
- Expiry C: `b3_client.py run --scenario expiry --nonce "$NONCE"`, with the IPC flags. Client remains alive while renewal stops.

Capture independent host USB evidence via the separately authorized passive package using a duration that covers baseline, active period and at least five seconds after the later of barrier and last successful completion. Each case has a hard 5 s TX limit and idle expiry 750 ms. Closed state and zero new writes are checked after each case. Save private status and export trace promptly before opening the next case via b3_client.py status and trace. Held records are bounded to 64; they are volatile and cannot survive Owner restart. Use owner_evidence.py with the passive package decode module on PYTHONPATH. Export Owner-generated safety_lost, trace_drops, gate and barrier and separately generated client/supervisor trigger event. Never synthesize missing fields. Do not reuse or change the prior marker. Revoke by deleting only the B3 marker as root. On loss of safe state or USB evidence, revoke immediately, retain isolation and do not claim a PASS or a proven queue drain. If the writer hangs, the gate/ACK cannot establish a bound until the call returns.

Sample budget proposals for independent audit. Manual origin = client monotonic immediately before revoke, 150 ms gate and 250 ms host stop. This budgets IPC/scheduling then a separate 100 ms transport margin. Client termination origin = supervisor monotonic just before signaling, with exit bracketed independently by pidfd, 250 ms gate and 350 ms stop. This budgets scheduling and process reaping then the same transport margin. Expiry origin = last accepted renewal, 825 ms gate and 850 ms stop, based on 750 ms idle and existing standalone 850 ms proposal. These are predeclared thresholds. They are not validated performance of the combined profile. PASS requires intended stop reason, no late Owner write, all matched successful frames within the respective host deadline, uninterrupted guards and complete capture/clock evidence. Breached safety/late write or measured budget overrun is FAIL. Missing process/clock evidence, loss, incomplete frames or an unproven barrier is INCONCLUSIVE. USB completion never yields independent physical last-bit timing.
