# Фізичне встановлення SRC Observer

Ця інструкція підготовлена офлайн. Виконувати фізичні кроки лише після окремого дозволу. Погоджений Observer має 341 байт, SHA256 960f125c87258957cf07c2c13c5c83c4395f478fa0758fbffbd0263b98e49499, стандартний CRC32 81ff20e2, CRC у варіанті ArduPilot MAVFTP 3510a502. У mock викликає read-only getter, millis та STATUSTEXT з інтервалом 500 мс. Інструкція не опубліковує адресу Pi або хеші фактичних файлів SD.

## Гальма і фізична підготовка

Приватний baseline підтверджено 4/4 SHA256. Фактичний brake script керує SERVO5/SERVO6 через функції 94/95. Вимоги скрипта — 999 мкс для HOLD і 2000 мкс для RELEASE, крок до 300 мкс за 50 мс, lease 350 мс, обмеження RELEASE 3 с. При DISARMED і успішній ініціалізації перший update виконується одразу та встановлює 999 мкс на обох виходах. Втрата потрібного KEEP або RC під час RELEASE переводить ціль у HOLD через ramp, доки Lua виконується. Гілка ARMED оновлює внутрішній стан і виходить до запису PWM. Помилка assertion або відсутність Lua означає відсутність гарантії, що скрипт встановив PWM.

Під час втрати живлення або перезапуску Lua цей код не контролює PWM. Між припиненням старого циклу та першим новим update можливі втрата сигналу, утримання попереднього значення або апаратний failsafe. Зусилля й положення гальм залежатимуть від живлення сервошини, типу сервоприводів, поведінки за втрати сигналу та механіки. Фізичне відпускання не виключене, його не перевіряли. Зафіксувати шасі незалежно від гальм, залишити тягові VESC знеструмленими, усунути доступ до коліс і приводів. Перед відключенням визначити всі джерела живлення контролера та окреме живлення гальм. Не перемикати гальма для перевірки. [Порти Pixhawk 6C](https://docs.holybro.com/autopilot/pixhawk-6c/pixhawk-6c-ports)

## Перед вимкненням і Owner

1. Через чинний B2 підтвердити один Owner, heartbeat < 1.5 с, HOLD, DISARMED, inhibit, STOP latch, TX disabled/sent=0. Записати стан гальмівних виходів і PID. При нестачі доказів зупинитися. Не запускати діагностичних завдань після передперевірки.
2. Попередній backup закрив усі файлові сесії. Перевірити відсутність FTP drop-in і marker, завершення останнього погодженого DataFlash-завдання та LOG_REQUEST_END після нього. У B2 статус не експортує глобального active-job або файлових дескрипторів DataFlash прошивки. Якщо статус останнього завдання невідомий, з'ясувати за його результатом і журналом до вимкнення. LOG_DISARMED=0 саме по собі не підтверджує відсутність усіх записів на SD.
3. Штатний Owner уміє перепідключатися, але для цієї процедури погоджено зупинити його перед USB, щоб контролювати момент нового з'єднання й почати новий процес без попереднього TIMESYNC. Залишити inhibit marker, STOP latch, DB і B2 drop-in. Не виконувати STOP reset. Зупинити служби тільки командою `sudo systemctl stop ugv-hmi.service`. Перевірити `systemctl show ugv-hmi.service -p ActiveState -p MainPID` (inactive і PID 0) та список Owner через `sudo /usr/local/libexec/ugv-pixhawk-owners` (повний скан, 0 Owner). Перед stop відкликати стару Lua-атестацію, якщо вона існує.
4. Від'єднати USB та всі фактичні живлення Pixhawk, зокрема POWER1/POWER2, якщо підключені. Pi залишити ввімкненим. Переконатися, що Pixhawk повністю знеструмлений і USB пристрій зник. Погаслі LED самі по собі не замінюють перевірку живлення. Вилучити microSD лише тоді.

## Windows

Використати приватний baseline SHA256SUMS зі збереженої копії. Одержати Observer через стандартний OpenSSH SCP і звірити хеш:
`(Get-FileHash -Algorithm SHA256 -LiteralPath .\stage3_src_observer.lua).Hash`.
Перевірити номер і букву саме картки Pixhawk, далі виконати:

```powershell
.\Install-Observer.ps1 -Action Install -CardRoot 'E:\' -Baseline .\SHA256SUMS -Observer .\stage3_src_observer.lua
```

Скрипт перевіряє baseline чотирьох файлів до запису та після, відхиляє цільове ім'я незалежно від регістру і копіює з overwrite=false. Усі п'ять хешів перевіряються перед вилученням. У разі помилки зупинитися, без повторного запису або форматування картки. Використати штатне Windows Eject і дочекатися дозволу на фізичне вилучення. [Windows File.Copy](https://learn.microsoft.com/dotnet/api/system.io.file.copy)

## Power-on і післязапускова перевірка

1. Вставити microSD у знеструмлений Pixhawk. Переконатися, що шасі досі зафіксоване та VESC знеструмлені. Повернути погоджені джерела живлення Pixhawk й той самий USB. Дочекатися появи стабільного by-id. Перевірити 0 Owner і тільки тоді виконати `sudo systemctl start ugv-hmi.service`. Якщо штатний Unix-сокет залишився, звірити його з конфігурацією, PID 0 та відсутністю слухача або з'єднання через `sudo ss -xap`. Не стартувати паралельний процес. Залишковий сокет прибирати лише після перевірки відсутності активного власника за штатною процедурою.
2. Порівняти активний drop-in із збереженим B2. Перевірити active/running, один Owner, HTTP 200, свіжий HOLD/DISARMED, inhibit, STOP latch, TX disabled/sent=0. За відсутності heartbeat або аномалій виходів зупинити діагностику і залишити тягу ізольованою.
3. Через штатну read-only діагностику перевірити свіжі SERVO5/6 PWM, очікуваний HOLD 999 мкс та STATUSTEXT про brake. Якщо PWM відсутні, потрібен зовнішній пасивний вимір на сигналі. Оператор окремо підтверджує механічно прикладені гальма на зафіксованому стенді, без RELEASE. Вихід PWM або ready-повідомлення окремо не доводять сили затиску.
4. Перевірити системний журнал і STATUSTEXT від нового boot на Lua load/assertion errors та out-of-memory. Зробити live readback через чинний B2 для LOG_DISARMED=0, SCR_ENABLE=1, SCR_HEAP_SIZE=204800. Відсутність помилок у журналі має супроводжуватися позитивним доказом роботи brake і Observer.
5. Отримати новий TIMESYNC через B2 і записати RTT та похибку. Лише після фізично підтвердженого нового boot і pinned SHA256 створити погоджену root-owned Lua-атестацію формату `B2 LUA <Pi boot id> <SHA256>`. Чинний B2 перевіряє Pi boot ID, тому при наступному reset Pixhawk без reset Pi атестацію потрібно відкликати й прив'язати наново. Не покладатися на стару атестацію.
6. Поки anchor свіжий, перевіряти STATUSTEXT S3SRC1 лише від sysid/compid 1/1 на Owner, зі зростанням мітки FC і очікуваним інтервалом 500 мс. Підтримувати anchor віком до 3 с. Вік доказу SRC має бути меншим за 1 с. Індекс 0/1/2 відповідає SRC1/SRC2/SRC3. Окремо записати свіжість EKF_STATUS_REPORT та LOCAL_POSITION_NED. Відсутнє повідомлення чи валідні XY не підміняти значенням з getter.

## Rollback

При Lua-помилці, аномалії brake або порушенні guard припинити діагностику, залишити тягу ізольованою та відкликати атестацію. Повторити контрольоване вимкнення і фізичне вилучення карти. На Windows:
` .\Install-Observer.ps1 -Action Remove -CardRoot 'E:\' -Baseline .\SHA256SUMS `.
Видаляється лише цільовий файл з погодженим SHA256. Якщо його вміст відрізняється, скрипт зупиняється. Повторно підтвердити чотири базові хеші, безпечно вилучити карту, виконати power-on і перевірити відновлення B2, фізичний HOLD brake і відсутність S3SRC1. Тяга залишається ізольованою.

Observer syntax і mock пройшли. PowerShell недоступний на Pi, Windows-команди переглянуто статично. Цю фізичну процедуру ще не запускали.
